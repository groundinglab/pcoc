# Policy

A policy sets the [Admission Process](../spec/04-Admission_Process.md#sec-15-4) §15.4 levers to values inside their ranges. It never changes a SPEC rule. The public specification is the six-doc pack under [`spec/`](../spec/README.md), tag `spec-2.3.0`.

The live policy on the public gate is [groundinglab-admission/gl-admit-v12.toml](groundinglab-admission/gl-admit-v12.toml). `GET /v1/health` on 28 Oct 2026 reported `policy_id` `gl-admit-v12`, `born_height` 972685, version 0.6.1, and gate commit `5a12aa2`. The file copies [gl-admit-v11.toml](groundinglab-admission/gl-admit-v11.toml) and omits `verify_cap_per_door_session`, so that lever is unset (no session cap). `gl-admit-v11` is the prior id. Its file keeps `status` `active` until that file is marked superseded, because those bytes stay pinned. [gl-admit-v10.toml](groundinglab-admission/gl-admit-v10.toml) keeps `status` `active` and its bytes stay pinned. [gl-admit-v9.toml](groundinglab-admission/gl-admit-v9.toml) is `superseded`. `deploy/gate.toml` names the v12 file, and the running host is on v12. `sticky_refuse` is `false` on v12 and on v11 (off for testing). An absent key means the same, so v10 is off without an edit. Set the key `true` to restore the stored-refuse short circuit. `leg_rate_floor` stays `{ p = 1, q = 10 }`. See [POLICY.md](groundinglab-admission/POLICY.md).

`born_height` in the v12 file is policy, not a SPEC lever. See [POLICY.md](groundinglab-admission/POLICY.md).
